# scripts/archive/ · 一次性补丁的归档区

> 立于 v0.195（债二 B1）。**这里放的是「已经跑完、结论已落进 `data/*.json`」的一次性补丁。**
> 它们留在这里是为了**留痕**——将来有人问「当年这条数据是怎么改的」，答案在文件头与 git 历史里。

## 规则（由 `test/scripts-hygiene-guard.mjs` 强制）

| 规则 | 守卫 | 含义 |
|---|---|---|
| 一次性补丁跑完就归档 | **P1** | `scripts/` 顶层不许出现 `fix-*` / `add-*` / `purge-*` / `strip-*` / `sync-*` / `tag-*` / `merge-*` / `_*` |
| 归档文件必须有标记 | **P2** | 文件头要有 `【已归档】`，并写明**结论去哪了** |
| 每个脚本都要声明生命周期 | **P3** | 文件头写「一次性」还是「长期」，不许靠猜 |
| 门禁脚本不许被归档 | **P4** | 双向对拍：`check.yml` 里 `run:` 到的脚本必须在顶层 |

## 为什么要有这些

`scripts/archive/` 里早就有 8 个文件（`_patch-v11`、`_patch-aliases-v36` …）——
说明**归档这个动作做过**，但没做成规范，于是又攒回 44 个（v0.195 立项时实测）。

根因很具体：`make-scripts-index.mjs` 只是**记账**（把 44 个如实列进索引），不是**约束**。
下一个 `fix-` 照样躺在 `scripts/` 根目录。⇒ 补的就是那个约束。

## ⚠ 前缀会误伤：三个例外

`PATCH_PREFIX` 只是命名习惯，不是事实。同一个前缀下混着三类东西，后两类被归档会出事：

| 文件 | 为什么不能归档 |
|---|---|
| `merge-duplicate-relations.mjs` | `validate.mjs` 会**主动建议用户跑它**（「关系重复…跑它合并」）⇒ 归档等于删掉一个出口 |
| `tag-script-lifetime.mjs` | 给脚本补生命周期声明的维护脚本，**P3 靠它才过得去** |
| `archive-one-offs.mjs` | 归档动作本身 |

⇒ 这份例外名单写在 `scripts/make-scripts-index.mjs` 的 `KEEP_TOOL`（**唯一来源**），
守卫与两个维护脚本都 import 它，不各抄一份。

⚠ 其中后两个是**自指陷阱**：守卫会先咬到自己的执行脚本。
凡是「用来维持规范」的脚本，都必须进这份名单。

## 维护脚本

| 脚本 | 干什么 |
|---|---|
| `archive-one-offs.mjs` | 把顶层的一次性补丁搬进来并加【已归档】标记；也给**上一轮**归档、缺标记的老文件补标记 |
| `tag-script-lifetime.mjs` | 给所有脚本文件头补【一次性】/【长期】声明（判据：门禁 / import / 文档 三类证据，不靠名字） |

两个都**幂等**，重跑不会重复插入。改脚本前先跑 `--write` 之外的预览模式。

## ⚠ 归档前必须确认两件事

**不许批量 `mv` 了事**：

1. 该脚本的结论**已经落进** `data/*.json` 或 CHANGELOG（否则归档＝丢未完成的工作）
2. 该脚本**没有未提交的改动**

## 查历史补丁

```bash
grep -rl "【已归档】" scripts/archive/          # 全部
git log --oneline -- scripts/archive/fix-3k-v144.mjs   # 某个补丁的来历
```

CHANGELOG 里 `## v0.xxx` 段落是主索引；注意 **v0.100~v0.128 那一批版本没有独立段落**
（记账方式的差异，不是工作没做），那批补丁的结论直接看 `data/*.json`。

# 书脉小程序（微信小程序）

把网页版的核心体验搬进微信：**人物关系图 + 搜索 + 两人关系 + 关系过滤 + 章节视图 + 剧透保护 + 时间旅行**，
数据全部打包在本地（不联网、不需要服务器、不需要备案域名）。

> 为什么不用 web-view 直接嵌网页：**个人主体的小程序不能用 `web-view`**，所以渲染层是重写的。

## 能力

- **图谱**：点节点看人物档案（身份 / 别名 / 结局 / 「他的一生」按章 / 关系与依据事件）；点连线看关系与依据事件
- **搜索**：全名 / 别名（字号、俗称、别的译名）；被折叠的人会自动展开那一层；被剧透保护挡住的人会提示"第 N 章才出场"；搜到后自动居中
- **两人关系**：点「人物 A / B」打开**可搜索的选择面板**（按名字 / 字号 / 别名搜，871 人也不用滚轮）→ 本地 BFS 最短路，每一跳给关系类型与依据事件，并在图上高亮整条链（尊重剧透保护与关系过滤）
- **关系过滤**：亲缘 5 类 × 线条 3 类 + 三个预设（只看亲缘 / 只看对立·伤害 / 重置）
- **章节视图**：◀▶ 翻章 + 「我读到这一章了」推进进度 + 点开看「本章谁初次登场 / 新关系 / 事件 / 地点」
- **剧透保护**：选读到第几章，未解锁的人物不显示名字、关系与事件都过滤
- **时间旅行**：滑块把图谱拨回第 N 章，只画当时已发生的关系（同盟→反目会随时间切换）；不会改你的真实进度
- 折叠（次要 / 提及 / 推导）、人数过滤（全部 / 中等 / 主要）、标签（主要 / 全部）、布局（分组·纵 / 分组·横 / 自由）
- **分享卡片**：一键生成 1200×900 的分享图（标题 + 统计 + 关系图 + 阵营图例），可「保存到相册」或「发送给好友」；微信右上角转发/朋友圈也会带上这张图
  - 卡片会**自动挑一套"铺得开"的布局**（大书的分组布局会排成一条长线 ⇒ 改用自由布局，副标题注明"（自动）"）
  - 标签**按节点密度定字号**、并在"上/右/左"三个候选位里找空位 ⇒ 三国 326 人也能放下 131 个名字
- **显示设置（无障碍）**：**色盲友好配色**（Okabe–Ito 八色，按阵营顺序分配）+ **字号**（小/中/大）；设置存本机
- 手势：拖动画布、双指缩放、双击复位

## 跑起来（三步）

1. **注册小程序账号**（个人主体可以）：<https://mp.weixin.qq.com/> → 注册 → 小程序 → 用身份证 + 人脸识别；
   在「开发管理 → 开发设置」拿到 **AppID**（想先看效果可以跳过这步，用开发者工具的**测试号**）
2. **装微信开发者工具**：<https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html>
3. **导入项目**：选择本目录 `miniprogram/`，填 AppID（或点「测试号」），编译即可看到图谱；
   点右上「预览」扫码可在真机上看

## 上线前必做（重要）

| 事项 | 说明 |
|---|---|
| **备案** | 小程序**注册后 20 个自然日内**必须完成备案（工信部），个人主体：身份证 + 人脸识别；未备案会被限制搜索与分享 |
| **类目** | 选**工具类**（如「工具 - 信息查询」）。**不要**选图书/出版/教育类——那些要前置审批资质 |
| **名称与头像** | 不得含「微信读书」等第三方商标字样，不得暗示官方合作；建议用「书脉」/「BookAtlas」+ 自己的图标 |
| **内容** | 本小程序只展示**阅读辅助数据**（人物/关系/事件的结构化整理），不含原著正文；用户数据只存本机 |
| **提交审核** | 上传代码 → 填写版本说明（写清"本地数据、无网络请求、无用户生成内容"）→ 提交 |

## 数据怎么更新

小程序的数据是**构建产物**（带预计算坐标），在仓库根目录跑：

```bash
node scripts/make-miniprogram-packs.mjs
```

会重新生成 `miniprogram/data/*.js`（三国 971KB / 百年孤独 94KB / 罪与罚 32KB，合计约 **1.07MB**）。
改了网页版的 `data/*.json` 之后记得重跑，两边的口径才一致。
> 上面几个数字与 `miniprogram/data/books.js` 里每本书的 `kb` 字段同源，以 `books.js` 为准，别手改本文档。

## 技术选择（为什么这么写）

- **不引 ECharts**：`echarts-for-weixin` 打包 1MB+，而我们的图是"坐标已知 + 自绘"就够；
  自绘 canvas 只用了 `arc / quadraticCurveTo / fillText / setLineDash`，代码 ~7KB
- **坐标在构建时算好**：分组·纵 / 分组·横 是确定性的；自由布局用 Node 里跑的简化 Fruchterman-Reingold
  （固定种子，可复现）——小程序端零布局开销
- **纯逻辑层**：`graph.js` 的口径与网页版 `js/app.js` 一致（剧透保护、时间旅行、折叠、关系过滤、
  两人关系、章节摘要），单独一层才能被 Node / 浏览器测试
- **体积**：数据 1.07MB + 代码 ~40KB < 主包 2MB 上限；如果以后书多了，把 `data/` 改成**分包**
  （单个分包 2MB、总计 20MB），或把大书放云端（需要备案域名）

## 书变多了怎么办（分包指南）

当前 3 本书共 1.07MB，主包 2MB 装得下。如果书继续增多，按以下步骤改成分包：

### 方案 A：按书分包（推荐）

1. 在 `app.json` 里配置 `subpackages`：
   ```json
   {
     "subpackages": [
       {
         "root": "books/solitude",
         "pages": ["index"]
       },
       {
         "root": "books/crime",
         "pages": ["index"]
       }
     ]
   }
   ```
2. 把 `miniprogram/data/<slug>.js` 移到对应分包目录下
3. 主包只保留 `books.js`（书目清单）和默认打开的那本书
4. 用户切换书时，分包按需加载

### 方案 B：独立分包（书特别多时）

- 每本书一个独立分包，可以独立运行
- 适合 10+ 本书的场景

### 注意事项

- 分包加载有延迟（约 200-500ms），可以在切换书时显示 loading
- 分包不能引用主包的代码，但主包可以引用分包
- 总包大小限制：主包 2MB + 所有分包 20MB

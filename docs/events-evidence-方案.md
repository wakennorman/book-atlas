# events 的证据分级 —— 方案

> 起因：v0.102 查出一条**伪造引文**（把转述写成了「」包着的原文）。
> 这是同一类错误第三次，第一次用机械指标代替了真正的判据。
> 这份方案是为了让"这句话到底是原文还是我的转述"**变成数据里可查的事实**，
> 而不是靠人肉记忆。

## 一、要解决的问题

`events[].text` 现在混着三种东西，读者和校验都分不清：

| 现在长什么样 | 实际是什么 | 有多��� |
|---|---|---|
| 「到我们回来的时候，它该更好了。」 | **转述被写成了引文**（原文根本没有这句） | 少量但性质最恶劣 |
| 「多么贪心的老太婆。」 | 转述，但仍标成引文 | 《罪与罚》14 条 |
| 桃园焚香结拜，誓同生死 | 老实转述，**没有引号** | 3385 条 |
| 「我们就把马孔多交给你了。」 | 真·逐字原文 | 29 条 |

**全库实测**（3810 条事件）：

```
                          事件总数   推导边   无引号   有引号   能在原文命中   命中不到
three-kingdoms               3479      91     3385        3            2          1
one-hundred-years             246      58      162       16           16         10
crime-and-punishment           85       0       60       11           11         14
合计                         3810     149     3607       54           29         25
```

⇒ **真正"带引号且能在原文逐字对上"的只有 29 条（0.8%）**。
   3607 条（94.7%）是老实转述、没冒充引文——问题不在它们。
   **要治理的是中间那 25 条**：有引号，但引号里的话原文没有。

## 二、字段设计

给 `events[]` 加一个字段，**只有两个值**，刻意做得笨：

```jsonc
{ "chapter": "第6章", "text": "……", "evidence": "quote" }      // text 整体是逐字原文
{ "chapter": "第6章", "text": "……", "evidence": "paraphrase" } // text 是我的转述
```

**不加第三档。** 我想过加 `"unverified"`（"还没核过"），但那会让
「没核过」和「核过是转述」混在一起——正是这次出问题的根源：
**没核 ≠ 是转述**。宁可让未核的先归 `paraphrase`（保守：宣称得更少），
也不要留一个"待定"状态然后默认当真。

### 为什么不用 `source: 'original' | 'summary'` 这类命名

`quote/paraphrase` 直接对应中文的「引文／转述」，不用翻译。
而且 `evidence` 这个词本身在提示"这是证据等级"，不是"这是内容类型"。

## 三、判定规则：**默认保守，不自动美化**

这是整个方案最要紧的一条。

```
evidence = 'quote'  当且仅当  该段文字能在原书里逐字定位到
evidence = 'paraphrase'  其他一切情况（默认）
```

**不是**"能定位就自动标 quote"。自动升级会把这个字段变成
"我又用机械指标代替判据"的第四个实例——比如转述里嵌了一句原文、
或者只有 6 个字能对上（「女贼」），都会被误判成 quote。

所以分两阶段：

### 阶段 1 · 机器先标，但**只标"确定是转述"**

脚本只做一件事：把**确定命中不到原文**的那 25 条标成 `paraphrase`，并把
被它删掉的「」**去掉**（去掉之后那句就不再冒充引文了）。

不动的：命中得到的 29 条、没引号的 3607 条（它们本来就是转述，
`evidence` 可以留空 = 默认 paraphrase，也可以在迁移时统一补上）。

**这一步就已经把最恶劣的问题消掉了**——那 25 条不会再有假引文。

### 阶段 2 · 人工只审 29 条

真正需要人判断的只有 29 条：它们引号里的话能在原文逐字找到，
但**仍然要确认它支持这条关系**（这正是 v0.101 那个错的行为人问题的域）。
一个人过 29 条，几分钟。

### 为什么"命中"也不能直接信

- 短引语（「女贼」这种 2—3 字）到处都会撞上
- 转述里嵌了原文的一个短句
- 不同版本字词有差异

所以命中 = "**可以**是引文"，不是"**就是**引文"。这也是阶段 2 存在的原因。

## 四、连带改动

| 位置 | 改什么 | 为什么 |
|---|---|---|
| `data/*.json` 的 `events[]` | 加 `evidence`，去掉 25 条里的假引号 | 本体 |
| `scripts/make-slim-packs.mjs` | 字段白名单加 `evidence` | 不加的话图包里没有，浏览器里读不到 |
| `scripts/check-graph-fields.mjs` | 不用改 | 它会自动检查"有值的字段在包里" |
| 前端事件展示 | 假引号去掉后文案更干净；`evidence==='quote'` 可加个小标记 | 让读者知道这句是原文 |
| `scripts/validate.mjs` | **不要**在这里加"必须是 quote"的检查 | 那是把上面的判定硬编码第二遍 |
| `scripts/audit-relation-actors.mjs` | C 级只对 `evidence==='quote'` 的事件报 | 有了字段就不用猜"逐字引文"长什么样 |

**注意 `validate.mjs` 那一行**：`looksVerbatim()` 这种"用启发式猜哪条是引文"的逻辑
正是这个方案要消灭的东西。字段落库之后，启发式就该删掉，而不是留着。

## 五、迁移顺序与风险

1. **加字段、跑脚本去掉 25 条假引号** —— 可回滚（改前先备份 json），
   不改任何关系结构，只改文案
2. **`make-slim-packs` 加白名单、重生成包** —— 机械
3. **人工过 29 条** —— 这一步**不能自动化**，也不该赶
4. **审计脚本改用 `evidence` 判级，删掉启发式** —— 放在最后，
   因为前 3 步做完它才有意义
5. 前端加"原文"标记 —— 可选，最后做

**风险点**：去掉假引号会改变那 25 条事件的文案。如果某处（前端？
测试？）硬编码引用了这些句子会断。改前 grep 一遍。

## 六、这套方案治不了什么

说清楚边界，免得又高估它：

- **治不了"行为人挂错"**（v0.101 那个错）。`evidence` 只回答"这句是不是原文"，
  不回答"这句里的『他』是谁"。那要读上下文。
- **治不了"关系类型编的"**（如「师徒」）。那是 `type` 字段的问题，
  不是 `events` 的问题。
- **治不了 3607 条老实转述的准确性**。它们本来就没冒充引文，
  但"转述有没有歪"是另一回事——三国那 3385 条从没被逐条核过。

⇒ 想覆盖这三类，得分别做：`check-kin-terms` 扩族谱（治称谓）、
逐本重读原著核关系类型与转述（治内容）。**都不是一次能做完的。**

## 七、一个更省事的替代方案（如果不想动数据）

如果只想要"读者不被假引文骗到"，可以跳过字段，只做一件事：

> 把 `events[].text` 里所有 `「」` **一律降级成 `『』`**（或去掉引号），
> 全库一次性脚本处理。

代价是**丢掉"这句确实是原文"的信息**（那 29 条也一起降级）。
好处是零新增字段、零前端改动、不可逆风险最低。

**取舍**：字段方案多花约半天，多保住 29 条"这是原文"的信息；
这个方案十分钟搞定，但以后没人分得出哪句是原文。
按这次教训的教训（别用机械指标冒充核实），我倾向**字段方案**——
因为"知道自己不知道什么"正是这个方案的核心。

## 八、第一步该做什么

**先只做阶段 1 的"去掉 25 条假引号"**，不加字段、不动前端。
理由：那 25 条是**唯一确定错误**的部分；字段和前端都可以等，
但假引文每多留一天，就多一天骗读者。

预计改动：3 个 json 文件 + 1 个一次性脚本，`check-version` / `validate` /
`make-slim-packs --check` 三步验证，10 分钟内可完成、可回滚。

# 新书处理规程（死规则）

> 这份规程针对的是「每加一本书都要重犯一遍的错」。
> 规则本身不随书变；**每加一本书只是执行它**。
> 违反其中任何一条，那本书就不算做完。

用户 2026-10-04 的原话：**「为了不再让你漏人物（人物不全）、漏人名（包括不同的译名、别名）、漏地点（包括地点和人物在关系画布的对应锁定问题）。你写个死规则，用这个项目处理每一本书时，都优先看完书籍，从原著书中的人物、事件、地点等需要处理的内容出发，而不是先去网上找其他资料，找资料扩充完善应该是把书中内容梳理清楚之后的事情。」**

---

## 零、先读原著，再碰资料

**唯一正确的顺序：**

```
① 读完原著（正文，不是简介、不是书评、不是百科）
        ↓
② 从原著里逐项抽取：人物 / 事件 / 地点 / 关系
        ↓
③ 自查：原著里出现过的每一个有名有姓的人，是不是都在图里？
        ↓
④ 缺口、歧义、译名差异 → 这时候才去查专业、权威、科学的资料来核对与补全
```

**明确禁止的顺序：**

- ❌ 先搜"百年孤独 人物关系"之类的二手资料 → 二手资料里缺谁你就跟着缺谁。
  实测就是这样漏的：布拉姆·施特劳斯式的"核心人物列表"不会列**皮埃特罗·克雷斯比**
  这种只出现几章的琴师，也不会列**堂梅尔乔·埃斯卡洛纳**这种在世时只有一句话的人物。
- ❌ 用百科/豆瓣/AI 生成的"主要人物"当骨架 → 那些列表按"重要度"排序，
  而本项目要的是**完整性**：一个人物哪怕只在一句话里出现、且是别人事件的参与者，
  他也该在图上有一条线。
- ❌ 用模型自身的知识直接当成"原著内容" → 模型会编。模型的知识只能进
  ④ 那一档（核对与补全），且必须能说清依据。

**"读完"的标准（可自查）：**

- 原著正文里每一个**有名有姓**的人，都能在 `characters` 里找到（或明确记录"查无此人/只有姓氏"）。
- 原著正文里每一个有专名的地点，都在 `places` 里。
- 用一条命令量化缺口（见下）。

## 一、人物：宁滥不缺，且必须能连线

**规则 1.1 —— 有名有姓就建档；但"能连上线"是建档的前提，不是可选项。**

判断标准只有一个：**他在原著正文里有没有被称呼过名字**。
有称呼就要建档，不管他出现了几章、不管他重不重要。
仅以姓氏/外号出现且再无其他称呼的，记进 `note`，并在缺口清单里留一条。

⚠ **"有名有姓"是必要条件，不是充分条件。** 建档前再问一句：

> **他在图上能连到谁？连不到就不该建。**

建了却连不到任何人 = 图上多一个**孤立节点**：搜不到任何关系、点进去只有一句话，
反而稀释了图。三种最常见的误建（v0.96 实际踩了两条，事后撤回）：

| 误建 | 为什么错 | 怎么避免 |
|---|---|---|
| 只出现 1 次、且**已故**的远亲 | 对故事线零参与，原文还常写"不记得有这些亲戚" | 数一下原文出现次数；已故且只 1 次 ⇒ 记进缺口清单不建档 |
| **同姓 ≠ 同人** | 「尼卡诺尔·乌略亚」≠「尼卡诺尔·雷伊纳神父」，只是名字里都有一个尼卡诺尔 | 加别名前必须找到**原文里把两个名字连起来的那一句**；找不到就别加 |
| 名字只出现 1 次、以姓氏相称，全名身份不明 | 硬建档＝**用推测填原著** | 记进缺口清单的"理由"栏，等拿到权威资料再补 |

被误建的条目**别只删数据**，写进 `data/<slug>.missing-ok.json` 的理由栏留痕，
免得下一轮又建一遍、又撤一遍。

**规则 1.2 —— 出现的每件事都要挂人。**

- `events[].chars` 必须包含事件里出现的每一个人。
  `scripts/link-mentions.mjs` 做"文案反挂"（正文提到却没进 `chars` 的自动补），**跑它**。
- 关系里的小事件同样要挂 `place`（见 §3）。

**规则 1.3 —— 血缘关系必须成对出现，而且必须可核对。**

⚠ 本节开头那句「数据模型里没有"父母"字段」是 **v0.94 及之前**的状况，
现在已经有 `parents` 了（见本节末尾）。留在这里是为了说明**为什么要有那个字段**。

父子关系曾经只是一条普通 `relations` 边。后果就是：
**漏一条边没有任何机制会发现它**，只能靠人记得加。

> 这条已经被用户抓到过：「奥雷里亚诺·布恩迪亚上校」和
> 「奥雷里亚诺第二 / 何塞·阿尔卡蒂奥第二 / 美人儿蕾梅黛丝」
> 明明是叔侄，图上却**一条线都没有**。

⇒ **已于 v0.95 实现**：给人物加了显式的 `parents: []`，
`validate.mjs` 双向校验——

- 声明了 `parents` 却没有对应的父子边 ⇒ **error**（漏边必被抓住）
- 有父子边但双方都没用 `parents` 登记 ⇒ **warn**（当迁移清单用，逐条消）

父子边的措辞要先剥掉旁系/姻亲词（「父子（父亲为皮埃特罗）」「婆媳」「养母女」
这类不算直系亲子），判定函数 `isParentEdge()` 在 `scripts/validate.mjs` 里，
带 11 个正例 / 17 个反例的单测。

**血缘由结构化字段声明，边由脚本派生，而不是手工维护一堆看不见全貌的边。**
注意当前两本书的 `parents` 声明数还很少（百年孤独 1 人），
warn 会列出所有未登记的亲子边——那是**待办清单**，不是可以忽略的提示。

**规则 1.4 —— 别人事件里当主角的人，不能只出现在别人的关系线上。**

实测：「维希塔香」教「阿尔卡蒂奥」和「阿玛兰妲」学瓜希拉语，
结果她的关系线上只有阿尔卡蒂奥和乌尔苏拉——**阿玛兰妲那条边漏了**。
判据：任一人物的 `note` / `desc` / 关系小事件里提到的人，必须有边。
`link-mentions.mjs` 就是干这个的，别跳。

## 二、人名：译名、别名、身份指代三样东西要分开

**规则 2.1 —— 一条记录里装不下三样东西，必须给类型。**

`aliases: []` 一个字段同时装着三类东西（README:282 那条原则当初就是为"搜不到"加的，
它是对的，但少了类型）：

| 类别 | 例子 | 界面措辞 | 字段 |
|---|---|---|---|
| **异译本名** | 比西塔西翁、霍塞·阿卡迪奥·布恩迪亚、拉斯科利尼科夫 | **又译 / 旧译** | `altNames: []` |
| **昵称·外号·简称·小名·乳名·称号** | 老何塞、巨人、上校、行刑队上尉、书店老板、梅梅 | **别名 / 昵称** | `aliases: []` |
| **身份指代**（本质是 note） | 乌尔苏拉的父亲、罗佳的母亲、卢仁律师、侦查科长 | 不算别名，但**必须保留可搜** | `note`（必要时也留在 `aliases` 里保搜索） |

**规则 2.2 —— 译名必须"解释清楚"是同一个人，不能只做到"搜得到"。**

踩过的坑：`比西塔西翁` 被塞进 `aliases` 之后搜得到你了，
但界面上一律渲染成「别名：比西塔西翁」，用户**认不出这就是维希塔香**，于是不点进去，
于是"搜出来了又等于没搜出来"。

⇒ 搜索联想结果必须显示「维希塔香（又译 比西塔西翁）」这类说明；
长度放不下时用悬停浮层，不许直接省略了事（用户 2026-10-04 的原话："鼠标悬停时弹窗展示可以吧？或者其他方法你看着办"）。

**规则 2.3 —— 一条别名里同时含"译名差异"和"绰号/序号"时，拆开写。**

实测：`奥雷良诺·布恩迪亚上校`（译名 + 称号）、`霍塞·阿卡迪奥（第二代）`（译名 + 序号）、
`美人儿雷梅苔丝`（绰号 + 译名）。
`altNames` **不必是 `aliases` 的子集** —— 它的职责只有「供搜索」和「供界面标成又译」，
所以写拆干净的变体即可（`altNames: ["奥雷良诺·布恩迪亚"]`），原混合串留在 `aliases` 里继续可搜。

**规则 2.4 —— 跑搜索命中率审计。**

```bash
node scripts/audit-search.mjs --all            # 只报告
node scripts/audit-search.mjs --all --write    # 自动补译名变体
```
它会报：别名覆盖率、**缺译名变体**、疑似漏人（"姓氏+称呼"出现 ≥2 次的）、
去括号后同名冲突。**"缺译名变体"必须清零才算完。**

**规则 2.5 —— v0.96 补：`altNames` 以前是"只有作者看得见"的字段。**

v0.95 引入 `altNames` 时只接了 `audit-search.mjs`、编辑器输入框、`draft.mjs`、
README jsonc，**`js/app.js` 里一次都没出现过** —— 也就是说按规则 2.3 写进去的
`altNames`，**在网页上搜不到、也看不见**。而用户报的正是"漏人名（包括不同的译名）"。

已修四处（三处判"搜得到"、一处判"已知"，口径必须一致）：

| 位置 | 作用 |
|---|---|
| `comboItems()` ＋ `attachCombo` 的 `open()` | 搜索联想与过滤认 `altNames` |
| 搜索框回车的 `match` | 直接搜译名能选到人 |
| `pathCharId()` | 两人关系链的输入框认 `altNames` |
| `audit-search.mjs` 的两处 `pool` | **否则会把已在 `altNames` 里的译名误报成"漏人"/"缺译名变体"** |

显示：搜索联想里内联渲染「（又译 X、Y）」，人物卡与人物志各加一行「又译：…」，
EPUB 导出写进「姓名」行。`altNames` 超过 2 个时截到 2 个并挂 `data-tip-full`，
交给全文浮层（v0.96）悬停补全。

⚠ **`--write` 仍把自动检测到的译名写进 `aliases` 而不是 `altNames`**
（`audit-search.mjs` 第 124 行），这是**故意保留**的：`aliases` 会被画布标签、
导出等更多地方读到，直接搬走会造成视觉回退。两者的分工现在是：

- `aliases` —— 昵称/外号/简称，以及工具自动补的译名（**会被画布标签等更多地方显示**）
- `altNames` —— 手工标注的"这是另一个译本"（**多一处「又译」标注**，同样可搜）

**两个字段都参与搜索**，所以"写哪个"只影响**显示措辞**，不影响能不能搜到。

### 2.6 名字必须用**书里那个写法**，否则等于没有这个人（v0.97 新增）

这是本项目最阴险的一类错：**人数对得上、门禁全绿、只有真人对着书找人才撞上。**

《百年孤独》一本书就抓出 7 个，每一个单看都"完全合理"：

| 数据里原来写的 | 原著（范晔本）实际写法 | 为什么没被发现 |
|---|---|---|
| 维克多里奥·麦丁纳 | **维多利奥·梅迪纳** | 别名「维多里奥」连字都对不上，两个写法一起错 |
| 尼格罗曼塔 | **尼格罗曼妲** | 别名「尼格罗·曼塔」也是错的，0 次命中 |
| 加布里埃尔 | **加布列尔** | 别名「加夫列尔」0 次命中 |
| 阿方索 | **阿尔丰索** | 整个名字差一个字 |
| 皮拉尔·特内拉 | **庇拉尔·特尔内拉** | 别名「皮拉·苔列娜」0 次命中 |
| 特兰奇丽娜·**玛丽亚**… | 特兰奇丽娜·**玛利亚**… | 一字之差 |
| 尼卡诺尔·雷伊纳**神父** | 尼卡诺尔·雷伊纳**神甫** | 「神父」是通称，不是本书用字 |

**铁律三条：**

1. **主名与 `aliases` 加起来，必须至少有一个形式在原文里出现过。**
   用 §四 的第 0.6 步查：`node scripts/audit-against-text.mjs data/xx.json 原文.txt --names`
   （有搜不到的人就非零退出。）
2. **同一个名字形式不许挂在两个人物身上。**
   `validate.mjs` 会报（warn）。真实撞到的例子：黄锦炎译本里的「霍塞·阿卡迪奥第二」
   同时挂在「何塞·阿尔卡蒂奥（第二代）」和「何塞·阿尔卡蒂奥第二」名下——
   **两个完全不同的人**，搜到它只能落到其中一个。
   ⚠ 判断依据要看**那个译本自己怎么区分**，别想当然：黄锦炎是靠**带不带姓**区分父子的
   （`霍塞·阿卡迪奥·布恩迪亚` 是创始人，光杆的 `霍塞·阿卡迪奥` 是他儿子），
   所以创始人身上就不该留光杆形式。
3. **括注（「（第二代）」「（第六代）」）只是给读者消歧的标记，原文里不会有。**
   `--names` 会自动剥掉括注再匹配；写别名时不要把括注当成名字的一部分。

⚠ **这一类错在版本库里查不出来** —— 原著文本不在仓库里。
`validate.mjs` 只能查 `altNames` 的卫生（空值 / 等于主名 / 字段内重复）和撞名，
**查不出"别名本身写错了"**。所以 §四 第 0.6 步是手跑项，不是可选项。

## 三、地点：范围、锁定、空范围三件事

**规则 3.1 —— 每个地点都要有介绍。** `places[].desc` 不许为空（`test/place.mjs` 有断言）。

**规则 3.2 —— 地点关联人物的范围是闭合的，且必须能连上。**

范围 = 该地点事件涉及的人 ∪ 该地点关系事件的两端。
**地点筛选必须全局生效**：按地点筛选后点人物，只在范围内展开；
点到范围外的人**自动取消筛选**，而不是偷偷把全部关系放出来。

**规则 3.3 —— 空范围要明说，不能静默。**

有些地点一条事件/关系事件都没挂（《罪与罚》的「广场（干草广场）」）。
静默的空集合筛选 = 画面什么都不变 = 用户以为点坏了。
⇒ 明确提示「还没有关联的人物或事件」，且**不留下空锁**。

**规则 3.4 —— 地点筛选后画布必须有东西可看。**

这是最容易复发的一条，见 §五。

## 四、交付前的自查流程（每本书照跑一遍）

```bash
# 0) 找原著正文，落到本地（scripts/extract-epub.mjs 可零依赖抽文）
node scripts/extract-epub.mjs book.epub out.txt

# 0.5) 对着原著核缺口（规程 §零 第③步的工具，v0.96 新增）
#      audit-search.mjs 扫的是本项目自己的文案，**看不到原著里提到谁**；
#      这个脚本扫原文，输出「疑似漏人 + 出现次数 + 首行原文片段」，逐条人工判定。
node scripts/audit-against-text.mjs data/xx.json 原文.txt
#      判完的噪声写进 data/xx.missing-ok.json（一行一个名字），下次不再报。
#      ⚠ 绝不要把"还没查清楚"或"确实是漏人"的候选丢进去 —— 那等于把缺口永久藏起来。

# 0.6) ⚠ 反过来再核一遍：**已建档的人名，原文里那个写法搜不搜得到**（v0.97 新增，必做）
node scripts/audit-against-text.mjs data/xx.json 原文.txt --names
#      上面 0.5 查的是"书里有、数据里没有"（漏人）；
#      这一步查的是**反方向**——数据里有这个人，但书上的写法一个都不命中，
#      读者拿着书里的名字点不进来。后者更阴险：人数对得上、门禁全绿，
#      只有真人对着书找人才会撞上。
#      有搜不到的人就非零退出，修完再跑一次。
#      《百年孤独》一本书就抓出 7 个（详见 §二 2.6）。
#      ⚠ 这一步**做不成 CI 门禁**：原著文本不在版本库里（extract-epub.mjs 注明）。
#         所以它是"拿到 epub 就必须手跑一次"的步骤，不是可选项。

# 1) 结构 / 引用 / 亲属 / 别名 / 时间区间 / parents 一致性
node scripts/validate.mjs data/xx.json

# 2) 搜索命中率：别名覆盖、缺译名变体、疑似漏人
node scripts/audit-search.mjs data/xx.json

# 3) 文案反挂：正文提到却没进 events[].chars 的人
node scripts/link-mentions.mjs data/xx.json --write

# 4) 族谱补全：从已有的亲子边推导祖孙/叔侄等
node scripts/derive-kin.mjs data/xx.json --write
node scripts/fix-parent-cycles.mjs data/xx.json --write

# 5) 清理：孤儿人物、孤儿地点
node scripts/prune.mjs data/xx.json --write

# 6) 小程序包同步（发布门禁会比对）
node scripts/make-miniprogram-packs.mjs
node scripts/check-packs-sync.mjs

# 7) ⚠ 网页端数据包同步 —— 忘了这步，网页读的还是旧数据
node scripts/make-slim-packs.mjs
node scripts/make-slim-packs.mjs --check

# 8) 跑**和 CI 一样**的门禁（不要凭"我记得我跑过那些命令"）
npm run gate
#    npm run gate -- --list        只看会跑什么
#    npm run gate -- --only 地点   只跑名字里含"地点"的步骤
#    npm run gate -- --skip-slow   跳过四个最慢的
```

> ⚠ **第 7 步千万别漏**（v0.96 实际踩过）。`data/books.json` 里每本书有两个文件：
> `file`（源）和 `graphFile`（`*.graph.json` 生成物）。**网页端 `loadBook` 优先读 `graphFile`**，
> 而小程序读的是 `miniprogram/data/*.js` —— 三个来源都可能不同步。
>
> 漏掉它的症状极具误导性：`validate --all` 全绿、`audit-search` 全绿、
> `check-packs-sync` 全绿、静态服务器也确实返回了新文件，
> 但页面和 `test/parity.mjs` 都在用**旧图包**（实测 parity 报"25 处不一致"，

## 五、视图层面的硬要求（新增，任何书都适用）

**规则 5.1 —— 任何"从图外导航进画布"的入口都必须建锁，并且锁定的人要真的在画布上。**

入口清单（右栏人名、关系列表、事件卡、时间轴芯片、阵营图例、地点筛选、搜索结果…）：
每一条建锁路径都要有测试（`test/lock.mjs`）。
判定标准是**量 zrender 里真实的可见图元**，不是看 `state`——`state` 里有节点不代表屏幕上画得出来。

**规则 5.2 —— 「世界单位→像素」的换算必须实测，不得推算。**

这是 v0.94 修的最贵的一个 bug：解析式（`pxScale / fitLast`）只在"画的就是全图"时准，
筛选到少数节点后 ECharts 会把绘制集合重新适配满画布，真实比例能差 **3.74 倍**，
于是"人在不在画面里"和"放大能不能救"两个判断同时反掉 ⇒ 点开就是空白。

⇒ 一律走 `unitPxNow()`（用 ECharts 公开的 `convertToPixel` 标定）。
**新增任何"把视野挪过去/放大"的逻辑时，不许自己算比例。**

**规则 5.3 —— 测视野相关行为时，每个用例重新加载页面。**

连点会让上一次的视野残留替这一次打掩护：实测连点 10 个地点测出"10/10 全过"，
而真实单点路径是 3/10。

## 六、禁止事项（总结）

1. ❌ 先看二手资料再补原著
2. ❌ 用模型自身的知识当原著内容（模型只能用于 ④ 核对补全，且要能说清依据）
3. ❌ 让人物"重要度"决定建不建档（有名有姓就建）——
   但反过来也错：**建了却连不到任何人**的（只出现 1 次的已故远亲、全名不明的单次提及），
   那是孤立节点，同样不该建。见 §一 规则 1.1 的对照表
4. ❌ 凭"同姓"就判定是同一个人（加别名前必须找到原文里把两个名字连起来的那一句）
5. ❌ 把译名/昵称/身份指代混在一个字段里没有类型
6. ❌ 只保证"搜得到"而不保证"认得出是同一个人"
7. ❌ 手工维护一堆看不见全貌的关系边（血缘必须可核对）
8. ❌ 范围为空时静默
9. ❌ 用 `state` 里的东西代替"屏幕上真的画出来了"作为判据
10. ❌ 推算世界单位→像素的换算
11. ❌ 连点式探针（每个用例重载页面）
12. ❌ 改了 `data/*.json` 就以为页面变了（网页端读的是 `*.graph.json` 生成物，见 §四 第 7 步）
13. ❌ **人名用"读起来合理"的写法，而不用书里那个写法** ——
    「维克多里奥」/「维多里奥」/「维多利奥」三个都像真的，但书上印的是第三个。
    名字对不上原文，这个人等于不存在，而门禁是全绿的。见 §二 2.6
14. ❌ 因为 `validate.mjs` 绿了就以为"名字都对"——
    它查不出"别名本身写错了"，因为原著文本不在版本库里。
    §四 第 0.6 步（`--names`）必须手跑，它不是可选项
